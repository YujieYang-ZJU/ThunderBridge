# 雷桥

**ThunderBridge · 两台 Mac，直接传文件。**

为雷雳网桥连接设计的原生 macOS 文件传输应用。浏览对方目录，上传本机文件，或把对方的文件下载回来。无需账号，文件通过本地网络直传。

`macOS 13+` · `Apple Silicon / Intel` · `v0.4.1`

[下载最新版](https://github.com/YujieYang-ZJU/ThunderBridge/releases/latest) · [版本记录](https://github.com/YujieYang-ZJU/ThunderBridge/releases)

## 把传输变简单

- **开启即发现** — 两边开启共享，自动识别并连接，无需输入 IP、端口或连接码。
- **双向传输** — 文件与整个文件夹都可上传、下载，支持从 Finder 拖入发送。
- **宽敞的文件列表** — 查看名称、大小与修改时间，支持多选；侧栏可隐藏，队列可展开调整高度。
- **断点续传** — 暂停、断线或重启后，重新连接原设备即可手动继续。
- **内容校验** — 接收后重新读取文件并校验 SHA-256，可导出 CSV / JSON 校验报告。
- **重复投递更省事** — 跳过相同内容，收藏常用目录，将一组来源和目标保存为投递方案。

## 开始使用

0.4.1 修复了雷雳网桥已连通却提示“所选网络不可用”的问题。直接识别所选网桥，不依赖默认上网路线。

从 Releases 下载 `ThunderBridge-v0.4.1-macOS-universal.zip`，解压后将 **雷桥.app** 放入「应用程序」。

1. 两台 Mac 安装并打开 **雷桥.app**，选择各自的雷雳网桥 IP 地址。
2. 两边点击 **开启本机共享**。只有一台可用 Mac 时自动连接；发现多台时，在「附近的 Mac」中点选。
3. 连接后，双击进入对方文件夹，或在路径栏输入路径，开始传输。

**上传到对方**：打开目标文件夹，点击「上传文件…」选择文件或文件夹，再点击「开始传输」。也可从 Finder 拖入，默认立即发送。

**下载到本机**：在对方列表中选中项目，点击「下载所选…」，选择本机保存位置即可。支持 ⌘ / ⇧ 多选，也可右键下载。

建议两端更新到 0.4.1；与 0.4.0 使用相同传输协议。雷雳网桥需先在 macOS 网络设置中配置，也可使用其他可达的本地 IPv4 接口。

## 文件如何处理

默认开启「只传变化文件」：同名同内容跳过，同名但内容不同则另存为带序号的副本，保留原文件。不删除目标目录中多出的文件。

支持普通文件与文件夹，包含中文名称、隐藏文件和空目录。保留文件修改时间与基本权限；不完整保留扩展属性、Finder 标签等元数据，暂不支持符号链接与特殊文件。需要传输这类目录时，可先在 Finder 中压缩。

雷桥用于文件传输，不提供镜像同步或完整系统备份。速度取决于网络与磁盘，准备和校验阶段也需要读取文件。

## 连接与权限

共享默认关闭，需手动开启。自动发现与连接仅使用所选网络，不会自动改走 Wi-Fi。停止共享会撤下设备广播、断开连接；再次开启后重新发现。手动断开连接后，可点选设备重连。

共享范围覆盖当前用户和应用有权访问的目录。**开启后，同一所选网络上的设备可直接浏览、下载和写入，请仅在可信网络使用。** 无码模式不进行设备身份认证；TLS 使用临时密钥交换加密传输，不能防止主动冒充设备。访问受保护目录仍需 macOS 授权。

首次启动时，请允许系统的本地网络访问与入站连接提示。找不到对方时，检查两边是否均开启共享、网络选择是否正确，以及本地网络权限与防火墙设置。

当前构建使用本地签名，尚未进行 Apple 开发者签名与公证。另一台 Mac 首次打开时，可能需要在「系统设置 → 隐私与安全性」中允许打开可信构建。

## 从源码构建

建议使用 Swift 6+ 工具链。以下命令在项目根目录执行；测试需 macOS 14+。

```sh
# 构建通用应用与压缩包，输出到 dist/
bash scripts/build-app.sh

# 运行测试
bash scripts/test.sh
```

原生 SwiftUI 界面，仅依赖 Apple 系统框架。核心传输逻辑位于 `Sources/BridgeCore`，应用界面位于 `Sources/ThunderBridge`。

当前版本已通过 45 项自动化测试，覆盖本机 Bonjour 自动发现、无连接码双向传输、重连、停止共享、加密协商与原有文件传输流程。已验证实际雷雳网桥的接口识别与限定接口监听；两台实体 Mac 的完整传输、速度与长期稳定性仍待实测；Intel 与 macOS 13 兼容性目前仅完成交叉构建。
